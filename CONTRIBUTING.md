# Как помочь проекту

Спасибо за интерес к Media Downloader! Любая помощь приветствуется: сообщения об ошибках, идеи и pull request'ы.

## Сообщить об ошибке

Перед созданием issue:

1. Убедитесь, что используете последнюю версию (или обновите движок: `py -m pip install -U yt-dlp`).
2. Проверьте, нет ли уже похожего issue.
3. Приложите максимум полезного:

- версия Windows;
- как запускаете: `.exe` или из исходников;
- что делали и что ожидали;
- **точный текст ошибки из журнала** (скопируйте из окна программы);
- скриншот, если уместно.

> ⚠️ Никогда не прикладывайте файл `cookies.txt` — в нём ваши личные данные авторизации.

## Предложить идею

Опишите, какую задачу хотите решить и почему это полезно. Один issue — одна идея.

## Pull request

1. Форкните репозиторий и создайте ветку от `master`:
   ```bat
   git checkout -b feature/короткое-описание
   ```
2. Установите окружение и зависимости:
   ```bat
   python -m venv venv
   venv\Scripts\activate
   pip install -r requirements.txt
   ```
3. Внесите изменения. Стиль кода:

   - Python 3.10+, отступы 4 пробела;
   - имена и комментарии можно на русском;
   - не добавляйте лишних зависимостей без необходимости;
   - не коммитьте `venv/`, `build/`, `dist/`, `.exe`, `cookies.txt` и личный конфиг.

4. Убедитесь, что файлы компилируются:
   ```bat
   python -m py_compile main.py downloader.py utils.py pot.py diagnostics.py ffmpeg_tools.py bootstrap.py release_notes.py prepare_ffmpeg.py
   ```
   Запустите проверки загрузчика, обновлений, очереди и интерфейса:
   ```bat
   python -m unittest discover -s tests -v
   ```
   Тесты используют временные папки, подмены внешних сервисов и локальный HTTP-сервер.
   Они не скачивают ролики из интернета и не изменяют личные настройки.
   Проверки Tk автоматически пропускаются, если графический экран недоступен.
   Проверки диагностики моделируют сбои фоновых задач, экспорта и записи на диск; настоящие нативные падения процесса не вызываются.
5. Сделайте коммит с понятным сообщением и откройте pull request.

## Релизы

Релиз выпускается только по явному решению владельца проекта.

1. Обновите `CHANGELOG.md`: добавьте раздел `## [X.Y.Z] — ГГГГ-ММ-ДД`.
2. Укажите версию в `version.txt` и прогоните проверки из предыдущего пункта.
3. Создайте тег и отправьте его:
   ```bat
   git tag -a vX.Y.Z -m "Media Downloader X.Y.Z"
   git push origin vX.Y.Z
   ```
4. Workflow `Release` соберёт exe и создаст **черновик** релиза с телом из
   `CHANGELOG.md`. Сам по себе тег ничего не публикует.
5. Скачайте exe из черновика и проверьте первый запуск и обновление.
6. Опубликуйте релиз вручную:
   ```bat
   gh release edit vX.Y.Z --draft=false
   ```

## Требования к интерфейсу

- Все пользовательские тексты — на русском.
- Не используйте эмодзи в самом интерфейсе программы.
- Не удаляйте существующие атрибуты виджетов в `main.py` без причины — на них завязана логика.
